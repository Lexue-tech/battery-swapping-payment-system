# 需求规格文档

## 项目概述
铁塔换电支付系统 - 先享后付签约流程静态交互Demo

## 范围说明
本次开发仅涉及前端页面与手机端交互，不接入任何真实后端接口，所有业务数据均通过前端Mock和页面状态保存实现。

## 平台边界
支付过程涉及以下3个平台：

1. 铁塔换电APP
2. 先享后付支付系统
3. 支付宝

## 功能需求

### 1. 铁塔换电APP收银台（p1）
#### 1.1 功能点描述
- 在铁塔换电APP收银台中新增“先享后付套餐”卡片
- 新增套餐视觉风格需与页面中已有套餐保持一致
- 用户点击“立即支付”后开始跳转到先享后付支付系统

#### 1.2 验收标准
- [ ] 页面展示至少一个先享后付套餐并与原有套餐风格统一
- [ ] 页面底部按钮点击后进入先享后付支付系统订单确认页

### 2. 先享后付支付系统 - 订单信息确认页（p2）
#### 2.1 功能点描述
- 页面整体风格与p1保持一致（颜色、卡片、按钮感受统一）
- 页面包含模拟产品信息（商品名称、金额、分期信息、订单号等）
- 点击主按钮后进入协议页

#### 2.2 验收标准
- [ ] 页面结构和视觉风格与参考图一致
- [ ] 产品信息为可见且完整的Mock数据
- [ ] 按钮点击可进入协议页

### 3. 先享后付支付系统 - 换电协议与电子签名（p3）
#### 3.1 功能点描述
- 协议正文内容采用：
  - `docs/requirements/pages/铁塔换电套餐协议/协议.md`
- 用户必须将协议阅读到最底端后，才可进行电子签名
- 电子签名需手动书写（手绘签名）
- 完成签名后才允许进入支付宝流程

#### 3.2 验收标准
- [ ] 协议内容完整展示
- [ ] 未滚动到底部时不可签名提交
- [ ] 用户可手写签名并成功提交
- [ ] 签名完成后进入支付宝身份认证流程

### 4. 支付宝 - 人脸认证流程（p4）
#### 4.1 功能点描述
- p4为三张连续页面，需在Demo中模拟完整流程
- 页面风格需与支付宝身份认证页面一致
- 人脸认证使用模拟头像/人脸，不调用真实能力
- 完成人脸采集后自动跳转到下一页面

#### 4.2 验收标准
- [ ] 至少包含“同意认证→采集人脸→眨眼完成”三步模拟
- [ ] 视觉风格接近支付宝身份认证页
- [ ] 人脸步骤完成后自动跳转到签约页

### 5. 支付宝 - 签约与支付密码（p5-1 / p5-2）
#### 5.1 功能点描述
- p5-1 页面标题必须改为“先享后付代扣签约”
- p5-2 页面模拟支付宝原生支付密码输入界面
- 密码输入完成后进入签约并支付完成页

#### 5.2 验收标准
- [ ] p5-1 标题文案准确为“先享后付代扣签约”
- [ ] p5-2 含6位密码输入交互与数字键盘模拟
- [ ] 输入6位后自动或按钮跳转至完成页

### 6. 先享后付支付系统 - 签约并支付完成（p5-3）
#### 6.1 功能点描述
- 从支付宝回跳至先享后付支付系统
- 展示“签约并支付完成”提示页
- 提供“返回商户/返回首页”交互，回到收银台成功态

#### 6.2 验收标准
- [ ] 完成页展示成功状态、订单信息、金额
- [ ] 支持点击返回商户并回到铁塔侧页面

## 页面跳转流程
```
铁塔换电APP（p1收银台）
  -> 先享后付支付系统（p2订单确认）
  -> 先享后付支付系统（p3协议阅读+电子签名）
  -> 支付宝（p4身份认证三步）
  -> 支付宝（p5-1先享后付代扣签约）
  -> 支付宝（p5-2支付密码）
  -> 先享后付支付系统（p5-3签约并支付完成）
  -> 铁塔换电APP（收银台成功态）
```

## 非功能需求

### 可用性需求
- 仅移动端H5体验
- 页面点击链路完整、可连续操作
- 兼容Android与iPhone主流浏览器

### 实现约束
- 纯静态页面（HTML/CSS/JavaScript）
- 后端服务全部Mock，不调用真实接口
- 数据仅在前端保存（内存、URL参数或LocalStorage）
